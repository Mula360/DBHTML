Core portal

Deploy the app, end to end

Six steps. The app is stateless — all persistent data lives in Supabase — so deployment is just "point a Next.js host at the right environment variables."

Finalise the database

In the Supabase SQL Editor, edit the names and emails arrays at the top of supabase/seed.sql with the real 10 committee members (order: President, VP-1, VP-2, Secretary, Treasurer, EC1–EC5) and run it. Then confirm the four baseline numbers in Settings → Baseline minimums once you're logged in — they default to 2 field trips, 8 meetings, 2 events, and 1 Pitta contribution per 180 days, with quorum at ⅓ of the EC.

Important

Only emails in the members table can ever log in. Seed the real people before sharing the link, or the first login attempt bounces.

Set up Resend (email)

Two things run on Resend:

  • App email — digests and reminders, sent straight from the app's API. Needs only RESEND_API_KEY and a verified sender.
  • Login links — sent by Supabase's auth system, which is rate-limited to ~4/hour unless you give it your own SMTP.

In Resend: create an account, add your domain and paste the DNS records it gives you at your registrar (SPF, DKIM, a return-path CNAME). Once it verifies, create an API key. Set RESEND_FROM_EMAIL to something on that domain, e.g. ec@deccanbirders.org.

Then in Supabase → Project Settings → Auth → SMTP Settings, enable custom SMTP with:

Host:      smtp.resend.com
Port:      465
Username:  resend
Password:  <your Resend API key>
Sender:    ec@deccanbirders.org
No domain yet?

You can launch on Resend's shared onboarding@resend.dev sender and Supabase's built-in email for a small pilot — just expect login links to be slow if several people sign in at once. Add the domain before rolling out to the whole committee.

Deploy to Vercel

vercel.com → Add New → Project → Import the Mula360/DBHTML repo (framework auto-detects as Next.js). Under Environment Variables, add all of these (Production + Preview):

NEXT_PUBLIC_SUPABASE_URL       = https://wmpuxjlfqujvfsehqjnt.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY  = <anon key, Supabase → Settings → API>
SUPABASE_SERVICE_ROLE_KEY      = <service_role key, same page>
NEXT_PUBLIC_APP_URL            = https://your-app.vercel.app
CRON_SECRET                    = <run: openssl rand -hex 24>
RESEND_API_KEY                 = <from step 2>
RESEND_FROM_EMAIL             = ec@deccanbirders.org

Click Deploy. The vercel.json in the repo already declares the cron schedule (30 2 * * * — 08:00 IST); Vercel picks it up automatically and, because CRON_SECRET is set, sends it as the bearer token the app checks for.

Plan note

Hobby allows one cron run per day (delayed up to an hour) — which is exactly what this needs. If you want cron to fire on the minute, or you consider a society tool "commercial", use Pro ($20/mo). Function timeout is 60s on both, and the daily job finishes in seconds.

Point Supabase auth at the live URL

Back in Supabase → Authentication → URL Configuration:

  • Site URL → https://your-app.vercel.app
  • Redirect URLs → add https://your-app.vercel.app/auth/callback

If you later add a custom domain, come back and update both. Redeploy the Vercel project after changing NEXT_PUBLIC_APP_URL.

Custom domain optional

In Vercel → Settings → Domains, add ec.deccanbirders.org and follow the CNAME instructions. Update NEXT_PUBLIC_APP_URL, the Supabase Site URL, and the redirect URL to match, then redeploy.

Smoke-test the live site

  • Open the URL → you're bounced to /login.
  • Enter a seeded member's email → magic-link email arrives → click → you land on the dashboard with your position badge.
  • Enter an email that isn't a member → "This app is for Deccan Birders EC members."
  • Create a meeting, mark attendance, watch the quorum banner change.
  • Trigger the cron manually to be sure the secret matches: 
    curl -H "Authorization: Bearer <CRON_SECRET>" \
  https://your-app.vercel.app/api/cron/daily
    It should return {"ok":true, ...} with an empty errors object.

Running on Railway instead

Railway works identically for the app, but its cron is a separate scheduled service rather than a config file. Deploy the repo as a web service with the same env vars, then add a second Cron service on the schedule 30 2 * * * with start command node scripts/trigger-cron.mjs and the NEXT_PUBLIC_APP_URL + CRON_SECRET vars. The repo ships both vercel.json and that script.

Phase 12 · optional

The meeting-bot & AI minutes pipeline

This is the only part that needs paid API keys. Left unconfigured, the "Activate meeting bot" button simply tells you it's off — nothing else in the portal depends on it.

What happens, start to finish

Secretaryadds the Google Meet link to the meeting, clicks "Activate bot"
→
Recall.aia bot joins the call, records & transcribes it
→
Webhook/api/recall-webhook stores the transcript on the meeting
→
Claudedrafts decisions, action items (matched to members), attendance
→
Draft MoMpre-filled for the Secretary to edit & approve — nothing is emailed automatically

Anthropic (Claude) setup

  1. Sign up at console.anthropic.com (phone verification; new accounts get $5 in free trial credit).
  2. Settings → Billing → optionally add a card and top up (minimum $5). Leave auto-reload off so it can never run up a bill — it just stops if credits run out.
  3. API Keys → Create Key. Add to Vercel: 
    ANTHROPIC_API_KEY = sk-ant-...
ANTHROPIC_MODEL   = claude-sonnet-4-6   # optional; this is the default
Cost, concretely

Claude Sonnet 4.6 is $3 per million input tokens, $15 per million output. A 1½-hour transcript is roughly 20,000 input tokens; the JSON of minutes is ~1,500 output. That's about $0.08 per meeting. Ten EC meetings a year ≈ $0.80/year — the free trial credit alone lasts years.

Recall.ai setup

  1. Sign up at recall.ai and create an API key (Pay-as-you-go plan; first 5 recording hours are free).
  2. Add a webhook pointing at your deployment: 
    URL:    https://your-app.vercel.app/api/recall-webhook
Events: transcript.done  (and bot status events)
  3. Pick any shared secret and set it in both places — Recall's webhook config and Vercel: 
    RECALL_API_KEY        = <from Recall>
RECALL_WEBHOOK_SECRET = <a random string, same on both sides>
    The webhook rejects any call whose x-recall-signature header (or ?secret=) doesn't match.
  4. Redeploy Vercel so the new variables take effect.
Cost, concretely

$0.50/hr recording + $0.15/hr transcription = $0.65/hr, billed to the second, no monthly fee. Ten 1½-hour meetings ≈ 15 hours ≈ $9.75/year (first year less the 5 free hours). Storage is free for 7 days — long enough for the webhook to pull the transcript — then $0.05/hr if you keep recordings, which this app doesn't ask it to.

Testing it

  • Create a meeting, paste a real meet.google.com link, click Activate meeting bot → chip turns to "Bot scheduled".
  • Start that Meet call yourself; the Recall bot joins within a minute. Say a couple of test "decisions" and "action items" out loud, then end the call.
  • Within a few minutes the chip flips to "Transcript received" and the Minutes section is pre-filled with a Draft MoM. Edit, approve, publish as normal.

Turning it off

Delete the three ANTHROPIC_* / RECALL_* variables (or just leave them unset). The pipeline code stays in the build but goes inert; minutes are then written by hand in the same editor.

Before the committee uses it

What else is needed

None of these are code — they're decisions and inputs only the committee can supply.

  • Real member data. The 10 names and emails, and their positions for the 2026–28 term. Optionally their eBird usernames and phone numbers (each member can fill their own later).
  • Confirm the baseline rules. The four minimums, the Pitta window (180 days), the compliance year (Sept–Aug), the quorum fraction (⅓), and whether an apology counts as attendance and whether virtual presence counts toward quorum. These come straight from the Roles & Responsibilities document and the bye-laws — set them once in Settings; every change is logged.
  • Confirm the 11 portfolio assignments. The seed uses a plausible mapping (Website → Secretary + EC1, etc.); the President or Secretary should set the real leads and support on each portfolio page.
  • The membership register. Export your current members spreadsheet to CSV; the import wizard maps the columns and previews before loading. Nothing about payments or emailing general members is in scope.
  • An administrator. Compliance-config and position changes sit with the President and Secretary only. Decide who holds it.
  • Meeting practice, if using the bot. Standardise on Google Meet, and agree that the Secretary tells participants at the top of each call that it's being recorded and transcribed.
  • A note to members. Their attendance, contributions and contact details live in this tool; the full membership register is visible to the register managers. Worth a line in the next EC email.
  • Backups. Supabase Free keeps automated backups for a short window; take a manual pg_dump before big changes, or move to Pro (7-day point-in-time recovery) once the register is loaded.

Reference

What was built, module by module

Thirteen screens behind a magic-link login, one shared sidebar, and a once-a-day background job. Every member can read almost everything; write access is granted per module by committee position.

The roles

Positions for the current term drive every permission: President VP-1 VP-2 Secretary Treasurer EC1–EC5. "Officer" means President or Secretary. VP-1 is also the Pitta Editor.

Dashboard /dashboard

Your landing page: position badge, your open action items grouped Overdue / Due this week / Upcoming, the next meetings and walks, and your four baseline-obligation tallies as coloured chips. The Treasurer also sees a pending-claims count.

Action Items /action-items

Every task the committee owns. Create with a title, assignee, due date, priority and portfolio tag; filter by any of those or search; open one to change status (Open → In progress → Done, or Dropped with a required reason), leave comments, and read the activity trail. Overdue is computed live — red past due, amber within three days.

anyone creates & comments assignee / creator / officer edits status officer deletes
Automated: a reminder 3 days before the due date, an alert to the assignee and the portfolio lead the day it goes overdue, and a running escalation digest to the President and Secretary for anything 7+ days overdue.

Meetings & MoM /meetings

The full meeting lifecycle: Draft → Agenda sent → In progress → MoM draft → Approved → Published. Sending the agenda emails it to every active member. An attendance grid records present / absent / apology and in-person / virtual per person, and recomputes quorum on every save. The minutes editor has structured sections — Decisions, Action Items (staged, then created for real on approval), Announcements, Next steps. Publishing emails the minutes to all members.

Secretary / President record attendance creator / officer drive the status & minutes
Rule 26: quorum = ⌈active EC × ⅓⌉, counted from in-person attendance (virtual too only if the bye-law flag is set). A no-quorum meeting shows a red "decisions not binding" banner, and publishing its minutes needs a typed PUBLISH ANYWAY and stamps a Rule 26 notice on the document.

Baseline Obligations /compliance

A 10 × 4 grid — every member against field trips coordinated, meetings attended, events assisted and Pitta contributions — coloured green / amber / red by pace: amber means keeping up with the calendar, red means behind it. Every number is derived from the other modules; nothing is entered here.

everyone reads President / Secretary edit the minimums in Settings
Automated: a mid-year pace alert to members who've fallen behind (copied to the Secretary), a Pitta nudge ~30 days before someone's rolling window lapses, and a full year-end compliance report to the officers on the configured date.

Walks & Field Trips /walks

Create a walk with location, date, meeting point, type and one or more coordinators. The eBird checklist and a Google Drive photo link are shown as buttons — there's deliberately no species list or photo upload here; eBird and Drive are the record. Members RSVP; after the walk a coordinator ticks who actually came.

anyone creates coordinator / Secretary marks attendance
Automated: a reminder the day before to everyone who RSVP'd "attending". Coordinating a walk feeds the field-trip obligation — co-coordinators each get full credit.

Annual Events & the AGM /events

Bird Race, Annual Dinner, AWC, HBA season, outreach and the AGM. Helpers add themselves; the event lead confirms who genuinely assisted (only confirmed assists count for compliance). Choosing type AGM with a date auto-builds the statutory checklist: the 15-day notice deadline, the nomination window, and warnings until the venue is named in the notice.

members self-add as helpers lead / Secretary confirm & edit
Automated: event reminders at T-30, T-7 and T-1; for an AGM, alerts to the Secretary at T-30 / T-20 / T-17 if the notice still hasn't gone out.

Statutory Tracker /statutory

Registrar filings, IT-department returns, audit deadlines — anything with an external authority and a due date. Items can carry a Drive link to the filed document and be marked "recurring yearly".

Secretary / President / Treasurer
Automated: a reminder to the Secretary 14 days before each due date; completed recurring items clone themselves into next year.

Pitta Newsletter /pitta

One row per issue (number, theme, target date, status Planning → Writing → Layout → Published). Inside an issue, a table of all 10 members where the editor types each person's contribution title. Publishing stamps every contribution with the publish date, which is what the rolling-window compliance check measures against.

VP-1 (Editor) / Secretary / President
The index shows a live list of who has no contribution inside the current window, with days since their last one.

Portfolio pages /portfolios/…

One page per portfolio (11 of them), driven by the current-term assignment. Each shows lead + support, a datestamped status-update log any member can post to, the open action items tagged to that portfolio, and linked events. HBA and AWC get extra panels — a 4-step season checklist and a per-site count / Wetlands-International flag; Bird Race gets a planning checklist.

anyone posts updates President / Secretary set the lead & support

Membership Register /membership

The ~570 general members — who never log in. Search and filter by status or type; import from CSV with a column-mapping wizard and a preview; export back to CSV for AGM quorum counts. "Mark renewed" sets the next due date a year out. Deletes are soft only.

VP-1, VP-2, EC2, Treasurer, Secretary, President — others see nothing here
Automated: nightly status recompute — Due 30 days before the renewal date, Lapsed 60 days after, Life always active — and a renewals-due list folded into the monthly digest for the Member Engagement portfolio and the Treasurer.

Reports /reports

A per-member annual report (obligations, action-item completion rate, walks coordinated / attended, Pitta history) laid out for print-to-PDF; and an EC-wide report — the obligations grid, a portfolio status summary, and an attendance heatmap of members against every meeting with a quorum row. Plus an archive of every digest the system has sent.

Documents /documents

A register of links, not files — bye-laws, the R&R framework, the MoM archive, finance and handover docs, grouped by category with bye-laws pinned to the top.

anyone adds Secretary / President delete

Expense Claims /finances

A member submits an amount, a description and a Drive receipt link; the Treasurer moves it Pending → Approved → Settled (or Rejects it), and the claimant is notified at each step. The Society's audited accounts stay the system of record — there's no ledger here.

any member submits their own Treasurer actions them

The once-a-day job

A single scheduled request at 08:00 IST runs everything below. It reads every threshold from the Settings config — nothing is hard-coded — and each task is isolated, so one failing never stops the rest. Every email it sends is mirrored to an in-app notification.

How access is enforced

  • Login is members-only. The form checks the email against the members table before sending a link, and the callback signs out any unknown email that somehow gets one.
  • Every table has row-level security in the database itself — not just the UI. A helper resolves your current-term position on each request, and policies decide what you can read and write. The membership register and other members' expense claims return zero rows to someone without the right position, even if they craft the request by hand. This is covered by an automated test that signs in as a plain member and asserts the walls hold.
  • The service key stays server-side — used only by the cron job, the login check and the meeting webhook, never sent to a browser.
  • The meeting webhook is authenticated by a shared secret; a request without it is rejected before anything is read.
